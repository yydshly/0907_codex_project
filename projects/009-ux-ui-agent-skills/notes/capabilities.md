## 17 个技能

| 技能目录 | 输入与任务 | 预期产物 | 依赖或限制 |
| --- | --- | --- | --- |
| `brandkit` | 品牌简报与视觉偏好 | Token、明暗主题、共享 CSS | 品牌策略由人提供，检查目标需配置 |

| `design-component` | 组件用途与交互需求 | 结构、变体、状态、无障碍规范 | 8 类状态按适用性选择，不是所有组件必须有加载或错误 |

| `apply-aesthetic` | 风格名称或视觉方向 | 配色、排版和视觉规则调整 | 品牌参考不代表官方实现 |
| `image-to-code` | 截图、线框或设计图 | 推导主题及界面实现 | 明确不保证像素级一致 |
| `redesign` | 已有页面与改造目标 | 先审查后修改的方案及实现 | 需要实际页面和业务行为依据 |

| `governance` | 设计系统维护需求 | 版本、贡献、弃用流程 | 由团队采用和执行 |

| `design-qa` | 项目质量保障目标 | CI 与回归检查方案 | 需绑定产品实际产物 |
| `performance` | 页面性能问题 | 性能分析与改进指导 | 指标需要真实测量 |

## 技能之外的辅助能力

- `tokens/`：设计基础数据；支持集中管理视觉值与语义映射。
- `components/`：按组件类别组织的规范，主要为 Markdown。
- `design-systems/library/`：138 个风格目录；抽样读取 Linear 文档，标题明确为受 Linear 启发的设计系统。
- `frameworks/`：框架协议和具体适配说明。
- `scripts/`：静态检查、浏览器检查、Token 构建与辅助生成工具。
- `evals/`：简报、产物评分器及作者运行记录。
- `.claude/commands/` 与 `.claude/agents/`：另有检查、交付、脚手架和设计批评相关入口；不计入上述 17 个技能目录。

## 如何组合

典型新页面：品牌简报 → `brandkit` / `design-tokens` → `design-component` → `design-code` → `a11y-audit` + `design-review`。

典型改版：已有页面 → `redesign` → 审查问题 → 调整主题与组件 → 对实际页面回归检查。

上述调用顺序属于工作流约定，执行依赖宿主模型与可用工具，并非独立工作流引擎提供的确定性调度。
