# 004 · Awesome Grok Bot：资料库与云端 AI 助手

> Grok Bot 是在平台托管的云电脑上执行任务、保存工作状态的 AI 产品；awesome-grok-bot 是介绍该产品的资料、案例和提示词目录。

## 先记住这两个对象

| 对象 | 是什么 | 对我们有什么作用 |
| --- | --- | --- |
| Grok Bot | 平台托管的 AI 助手产品，配有持久云电脑 | 接收任务，操作工具，交付并保存结果 |
| awesome-grok-bot | 非官方资源目录、案例集和提示词集 | 了解产品、找适用场景、借鉴工作方法 |

**不用先购买云服务器，也不是把这个仓库部署上去。** 使用官方产品时，平台提供运行环境；克隆本仓库只能得到研究资料和文档生成脚本，不能启动一个 Grok Bot。

官方目前只支持其托管的云电脑，不支持私有化部署或自带系统镜像。来源：[安全与部署说明](https://docs.x.ai/grok-bot/security)。

## 产品能做什么

可以把它理解成“配了一台云电脑的 AI 助手”：你通过聊天布置任务，它使用浏览器、终端、文件和已授权的连接器执行。你关闭自己的电脑后，云端工作仍能继续。

| 场景 | 可以执行的工作 | 可以留下的成果 |
| --- | --- | --- |
| 项目研究 | 阅读官方资料和代码，整理功能与差异 | 研究报告、来源链接、对比表 |
| 软件开发 | 编写代码、运行程序、检查结果 | 代码、测试记录、说明文档 |
| 定期跟踪 | 按计划检查指定网站或项目的变化 | 更新简报、历史记录 |
| 产品与运营 | 汇总反馈、分析数据、起草需求 | 分类表、分析报告、需求草稿 |
| 日常办公 | 整理日程、核对数据、准备材料 | 待办清单、表格、周报 |

这些是公开能力支持的任务方向，不是本研究逐项验证的成功承诺。参考：[电脑与应用](https://docs.x.ai/grok-bot/computer-and-apps)、[官方使用场景](https://docs.x.ai/grok-bot/use-cases)。

## “持久运行”和“沉淀”具体指什么

- **持久运行**：云端可以继续当前任务，也能通过例程按时间或支持的事件再次开始工作；不依赖个人电脑一直开机。它仍受任务范围、用量、工具可用性和人工接管环节限制，不会无限自主开发。
- **成果沉淀**：在持久工作区保存代码、资料和报告，后续任务可以接着使用。浏览器会话也可保留，但登录可能过期，临时目录和未保存状态不能当作可靠存储。
- **流程沉淀**：将成功做法整理成 Skill，明确步骤、判断规则、输出和验证方法；用 Routine 指定何时执行。主要是在保存方法和规则，不等于重新训练模型。

官方建议先做成功一次、保存技能、换一个输入测试，再设置例程。来源：[技能与例程](https://docs.x.ai/grok-bot/skills-routines-and-automations)。

## 底层原理：分两层理解

**资料库的实现**：`data/catalog.json` 保存资源条目 → `scripts/generate_readme.py` 检查多语言字段并生成中、英、日文 README 和活动页面。仓库还附有 10 类角色提示词。它不包含模型推理服务、智能体执行引擎或云电脑调度系统。

**产品的执行方式**：接收任务或触发事件 → 结合上下文与技能决定下一步 → 调用连接器、浏览器或终端 → 观察结果并继续 → 保存成果、汇报或请求人工处理。这是根据官方功能归纳的概念流程，未核实内部调度实现。

连接器适合结构化操作；浏览器用于缺少连接器或需要视觉操作的流程。多个 Bot 可以分工协作，但同一账号下共享电脑、文件和登录态，角色分工不等于权限隔离。模型选择由 Cursor 管理，不能根据产品名称认定它始终使用某一个 Grok 模型。来源：[总览](https://docs.x.ai/grok-bot/overview)、[电脑与应用](https://docs.x.ai/grok-bot/computer-and-apps)、[安全说明](https://docs.x.ai/grok-bot/security)。

## 对我们的意义与扩展方向

当前将它作为**场景和工作方法参考库**，不作为自建 AI 平台的代码基础。优先寻找我们经常重复、成果容易验收的任务，然后提取输入要求、执行步骤、数据入口、输出格式、验收标准和失败处理。

建议的首个试点是“开源项目研究”：输入仓库链接，固定输出项目定位、能力、原理、运行条件和采用建议。先用几个不同仓库验证准确性与返工量，再沉淀成自己的研究技能；需要周期更新时再增加例程。这是建议，尚未创建或运行自动化。

可扩展方向（本研究建议，非现有功能）：

1. 给案例增加真实输入、成果样例、成本和失败记录，形成经过验证的案例库。
2. 将角色提示词补全为业务技能包，明确验收与异常处理。
3. 接入自己的文档、数据和业务系统，建立任务状态、重试与防重复处理机制。
4. 用节省的人工时间、关键结论准确性、返工次数和运行成本衡量价值。

提示词需审核后采用。例如原仓库的邮件模板同时写“先只读”和“归档噪音”，而归档会改变邮箱状态，应在使用前消除冲突。参考：[原始提示词](https://github.com/RongleCat/awesome-grok-bot/blob/cb9239b9eda7486518ddbe96018696589aba5560/prompts/playbook-prompts.zh.md)。
