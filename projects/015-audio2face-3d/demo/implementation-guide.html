我们的目标

用户换自己的形象，继续使用同一套说话与动作能力。

输入一句话 → 人物给出回应 → 有声音、同步口型、适当表情与动作 → 说完回到自然待机。

人物资产→动作＋回复和语音→面部驱动→稳定与播放

0 · 先准备运行基础

本机环境

Python 独立环境、FFmpeg、浏览器。视频模型使用 PyTorch / CUDA；3D 推理使用 ONNX Runtime。本项目已在 Windows、RTX 4070 Laptop 8GB 上运行，不代表任意硬件都可直接复现。

代码与预训练权重

下载下方所选路线的库和模型权重，固定版本并校验文件。使用现成权重做推理；目前没有为每个用户训练专属模型。

素材与云服务

视频路线准备单人清晰照片；3D 路线准备可驱动的模型。MiniMax 对话、语音及 Hailuo 需要服务端密钥和相应额度，密钥保留在后端配置。

产物：可加载的模型、可用的云服务连接、人物素材和独立存储目录。

处理
统一图片格式与尺寸、分配人物 ID、保存来源散列。示例图可用远端 ImageGen 制作，用户上传不需要此工具。
产物
source.png ＋ avatar.json ＋ 独立人物目录
↓

A2把照片变成动作视频

Hailuo · 自然半身LivePortrait · 面部
输入
照片＋动作描述，或照片＋表情/姿态参数。
选择
Hailuo：生成头肩、身体和表情动作。
LivePortrait：提取外观与运动信息，变形并解码出转头、眨眼和微笑。
早期 LTX-Video：也是图生动作视频；本项目用远端 Space，当前上传页没有这个选项。
产物
各情绪的无台词动作 motion.mp4

当前准备六种动作。动作视频一旦保存，后续不同台词可以复用；补充或更换动作才需要再生成。

↓ 不论动作来自哪个模型，进入同一准备流程

A3为口型生成准备位置、蒙版与特征

facexlib：RetinaFace / FAN / ParseNetMuseTalk VAE缓存与平滑
输入
动作视频的每一帧。
处理
RetinaFace 找脸 → FAN 找关键点并帮助裁切 → ParseNet 分辨皮肤、嘴唇和口腔 → 自研规则确定融合蒙版 → VAE 编码面部。
产物
检测框 boxes / float_boxes ＋ 蒙版 masks ＋ 潜变量 latents ＋ 预览图

这是我们为 MuseTalk 搭的准备层，不是 LivePortrait 的库内原理。缓存是保存计算结果，不是训练一个新人物模型。

每次用户说话 · 生成新回复

A4生成“说什么”和“怎么说”

MiniMax 对话模型MiniMax TTS会话与情绪选择
输入
用户文字、本次会话上下文、角色设定。
处理
对话模型输出回复和情绪类别 → TTS 把文字合成声音 → 选择相应动作素材。当前输入是文字，尚未接入麦克风语音识别。
产物
回复文字 ＋ 情绪 intent ＋ speech.mp3 / audio.wav
↓ 新音频 ＋ 已准备动作视频及缓存

A5让嘴型匹配这一次的声音

MuseTalk：Whisper / U-Net / VAE动作时间调度
输入
A3 的动作缓存＋A4 的新音频。
处理
Whisper 提取音频特征，条件 U-Net 结合面部潜变量预测新画面，VAE 解码嘴部。半身版同时按音频能量调整动作节奏，并保持画面与缓存对齐。
产物
逐帧的新嘴部画面 ＋ 对应时间位置

Whisper 在这里不是把用户语音识别成文字。身体动作仍来自素材，台词不会自动创造新的挥手或拥抱动作。

↓

A6稳定画面、融合嘴部、加入声音

OpenCV / NumPy / SciPy / FFmpeg时序稳定与句尾回落
输入
原动作画面、新嘴部、蒙版与音频。
处理
用光流辅助稳定相邻帧，按蒙版柔和融合嘴部；根据语音活动逐渐收回嘴部替换；最后编码并合并音轨。
产物
result.mp4 ＋ 时间线与质量检查记录

句尾回落恢复的是原动作视频，不能保证原素材自身完全无嘴部微动。

↓

A7连续播放并等待下一次回应

Python 任务服务JavaScript 播放器
处理
管理排队、分段生成、取消、重播、人物隔离和待机切换。视频生成期间显示明确的等待状态。
产物
用户可以对话、观看人物说话、停止和重播
最终效果 A：照片人物有声音、口型、表情和已有身体动作

这是现有 8022 主流程；自然半身版完整验证了一个人物。当前为异步生成后播放，尚非实时视频通话；跨人物质量、动作循环与切换仍需优化。

两条路线共用什么？

可以共用对话模型、TTS、角色性格与业务状态。视频路线需要图像素材和口型重绘；3D 路线需要模型资产、绑定和渲染。它们并不需要彼此作为前置条件。

03 / DEFINITION OF DONE

最后要看到什么，才算实现目标

换人物仍然成立

不同照片使用同一流程，无需逐人改代码；照片不合适时明确提示。目前自然半身完成一个人物，仍需扩大验证。

说话和停顿自然

嘴型跟随声音，语音与视频同步；说完不继续异常张嘴，人物身份和嘴部细节稳定。

动作有连续性

倾听、思考、说话和待机衔接自然；情绪变化不突然跳姿态；长句循环不明显。这部分仍需优化。

成本与等待可接受

记录人物准备成本和每次回复耗时；缓存可复用，失败可恢复。已有视频可直接播放，实时通话尚未实现。

04 / IN THIS PROJECT

落到本项目，按哪些文件复现

这是实施与代码导航，不是已经验证过的空白机器一键安装包。已有下载脚本、环境记录与模型清单；不同路线分别准备依赖，启动脚本不会替你安装全部模型。

回复生成：minimax_dialogue.py → performance_worker.py → performance_postprocess.py → dialogue-segmented.js。

准备就绪后，项目目录运行 ./start-performance.ps1，再从“人物库”上传照片。现有运行环境沿用 .cache/sadtalker-venv 目录名，不表示当前主线使用 SadTalker。
