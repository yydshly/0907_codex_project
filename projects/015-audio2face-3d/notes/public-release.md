# 对外导览与效果录像发布记录

2026-09-08。对应 `docs/demos/015-audio2face-3d/` 的静态导览。

## 对外说明

- 3D 路线：音频驱动已适配的三维人物面部，再由渲染器显示口型与表情。实现为本地 Audio2Face Mark v2.3、独立适配和 Three.js。
- 视频路线：照片先生成动作视频，再根据音频重绘口型，合成最终说话视频。动作来自 Hailuo / 早期 LTX-Video 或本地 LivePortrait；口型由本地 MuseTalk 生成。
- 整体架构分别标出模型、输入输出、本地或远端、首次准备与回复生成；完整实施图和重读手册解释组件归属。

## 8020 效果录像

- 录制实际本地页面 `http://127.0.0.1:8020/`，没有生成新的动作或语音。
- 操作顺序：待机、原照片、原动作、连续播放欢迎/调皮/轻松回应三个场景、返回待机。
- 画面采用隔离 Chromium 页面逐帧截图并记录墙钟时间，源视口为 1440×1000；286 张画面，成片约 19.88 秒。
- 原片音轨根据浏览器 `playing` 事件和 `currentTime` 对齐后合成；不是录制系统音频或麦克风。输出编码为 30 fps，实际捕获平均约 14.39 fps，因此并非每秒 30 张独立捕获画面。
- 原始网页视频为 `timing-v5`。身体来自 LTX-Video，声音来自 Edge TTS `zh-TW-HsiaoChenNeural`，嘴部来自 MuseTalk 1.5 与本地稳定处理。不得标成 Audio2Face 或 MiniMax 生成的录像。
- 同时提供三段原始视频的 12 秒合集，供不经过网页截图采样的画质观察。
- 复录：安装 Playwright 与 Chromium，运行 `node scripts/record_showcase.cjs`，再运行 `python scripts/encode_showcase.py`。需要现有 8020 服务和完整片段。中间帧留在 Git 忽略的 `.cache/public-recording/`。

## 检查结果

- 录屏含 H.264 视频和 AAC 音轨，网页可正常播放。
- 三段音轨与原成片的对齐相关性分别约 0.999964、0.999975、0.999962。此检查证明音轨来源与时间对齐，不替代主观口型自然度评测。
- 1440×1000 和 390×844 浏览器检查：录屏加载、播放、手机无横向溢出、实施指引加载通过。
- 静态 Mark 真实三维数据加载通过；公开模式禁用上传推理。
- 已检查桌面完整导览与三维效果截图。
- 发布清单记录文件大小与 SHA256；文本先规范为 LF，再计算散列，便于与 Git 内容核对。

## 发布边界

只发布项目代码与说明、官方 Mark 可回放数据、选定虚构人物成片与网页录屏。公开页不依赖本机地址、密钥或私有 API。源码中的本地入口仍为运行本项目提供导航。

密钥、用户上传、运行时会话/审计 JSON、模型权重、下载的上游仓库、Camila 资产和截图均不包含在本次公开内容中。历史笔记可能引用未发布的本地审计文件；它们保存在原工作区用于排查。

Camila 仅限本地评估。Mark、各模型、代码和素材各自的来源与许可见 `demo/THIRD_PARTY_NOTICES.md`；不能把某个代码库的许可解释成所有资产的通用许可。

## 静态构建

运行 `python scripts/publish_static.py` 从显式页面与素材集合生成公开目录。该脚本不请求模型、不执行 Git 推送；需要本地已准备的 Mark 样例、录屏和原片合集。GitHub Pages 使用仓库 `main` 分支的 `/docs`。
