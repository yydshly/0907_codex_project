# 当前效果的优化与复用方案

2026-09-08，基于用户认可有明显改善的 tail-v4。本文为设计与实施顺序，尚未进行组件重构或接入实时聊天。

## 判断

当前已验证「原创肖像 → 半身动作视频 → 合成语音 → 嘴型重建 → 句末释放 → 匹配待机」这一离线流程可以工作。改善最明显的两次修正分别解决了实际接入错误和行为状态缺失：

1. ParseNet 口腔类别被遗漏，导致旧牙齿与新嘴型混合。修复类别映射后，抽查张嘴区域的覆盖恢复完整。
2. 音频结束后模型继续生成嘴型。tail-v4 保留尾音，平滑释放生成区域，再恢复同帧原动作，并接匹配姿态的待机。

值得复用的是这些规则与验证方法，而不是把当前三个 MP4 和页面复制到另一个项目。当前 8020 的照片视频链路采用 LTX-Video、TTS 和 MuseTalk；NVIDIA Audio2Face 的三维输出是另一条链路，不能混称。

## 仍可优化的效果

| 优先级 | 当前缺口 | 下一步 | 验收方式 |
| --- | --- | --- | --- |
| P0 | 仅处理最后静音，句中长停顿仍可能乱动 | 区分短暂停顿和说话结束。短暂停顿保留口部准备姿态，长停顿再缓慢降低嘴型权重；结合音频活动与 TTS 边界信息 | 长句、逗号、犹豫音、轻声尾音，不误切仍在发音的部分 |
| P0 | 素材质量限制成片，手部触脸会破坏融合 | 建立可说话动作素材筛选：脸部足够清楚、嘴部无遮挡、头部转角适中；先做自然点头、肩部和呼吸动作 | 同一音频对比不同素材，分别检查嘴部和人物身份 |
| P1 | 播放结束衔接已处理，但新一轮开口、打断、跨场景仍可能跳变 | 建立完整状态切换，并选择入口姿态与出口姿态接近的动作；必要时制作过渡片段 | 连续多轮、频繁打断、快速重播，观察姿态和音画时钟 |
| P1 | 当前待机是短片往返，久看有重复感 | 准备多个可衔接的待机片段，按姿态和视线匹配切换；限制频繁眨眼和点头 | 连续观察至少一分钟，检查倒放感、机械重复及切换跳变 |
| P1 | 说话期间牙齿模糊、嘴角细节变化 | 先固定清晰素材与完整遮罩，再比较生成模型或质量配置；把生成和合成分别评估 | 同素材、同音频的盲测，检查正常速度及局部慢放；不单看像素波动 |
| P2 | 台词、语气、表情和动作尚未统一控制 | 从业务回应产生受限的表演意图，例如安慰、调皮、轻微不满，再分别映射到语音、表情基调、动作 | 人工判断是否表达目标情绪；不把微笑素材标成生气 |

不优先继续加重嘴部图像平滑：它可能减少数值波动，同时损失发音细节。换生成模型也应在固定测试集上验证，不能假定换模型就一定更自然。

## 通用状态控制

推荐状态为 `idle → preparing → speaking → releasing → idle`，并允许 `speaking → interrupted → releasing/idle`。

- idle：只播放待机行为，不持续运行语音嘴型生成。
- preparing：等待媒体或预缓冲；不凭「请求已经返回」就开始张嘴。
- speaking：以实际音频播放时钟驱动嘴型、字幕和动作事件。
- releasing：保留尾音与短缓冲，把嘴部恢复到角色当前情绪下的放松姿态，不强制所有角色闭嘴。
- interrupted：取消过期任务、停止对应音频，清空播放队列，过渡到可用待机姿态。

这里的控制器应当是可复用逻辑。具体执行方式随后端不同：视频后端控制片段和局部混合权重；三维后端控制 blendshape、下颌与动画权重。

tail-v4 的 -60 dBFS、100 毫秒缓冲、220 毫秒释放只是在当前干净 TTS 上验证过的初始配置。实时音频、背景音乐、低声说话不能直接照搬。实时模式还需有迟滞与最短保持时间的语音活动检测，避免每次呼吸、停顿都触发闭嘴。

## 最小可复用模块

| 模块 | 输入 | 输出与责任 |
| --- | --- | --- |
| 角色资源包 | 肖像、动作、待机、声音配置 | 角色身份、素材 URI、姿态/情绪标签、适用范围与来源记录 |
| 语音适配器 | 文本、音色、语气参数 | 音频、采样率、真实时长、可用的字词边界；标明供应方是否支持情绪控制 |
| 动作选择器 | 表演意图、当前姿态、语音时长 | 可用的说话底片、入口/出口姿态和动作事件 |
| 嘴型与渲染适配器 | 动作素材、音频、时间轴 | 帧/视频或带时间戳的三维参数，明确输出类型、帧率、遮罩语义与能力边界 |
| 状态控制器与播放器 | 媒体包、时间轴、用户打断 | 开口、停顿、收尾、待机和取消；处理过期异步响应 |
| 验证与版本记录 | 输入、各阶段输出、模型/配置版本 | 可追溯成片、检查报告、可回放对照和失败原因 |

不要强制把三维参数与视频帧塞进一个模糊的 `generate()` 返回值。接口可共享时间轴和状态，媒体结果应使用明确的类型，并由对应渲染器消费。

## 对外调用的目标形态

以下是拟定接口，并非当前已可调用的 SDK：

```python
job = avatar.render(
    character="xiaoqing",
    text="你今天还好吗？",
    intent="gentle",
    output="video",
)
```

最终应返回 `RenderBundle`：`video_uri`、`audio_uri`、`idle_uri`、`timeline_uri`、`report_uri`、`manifest_uri`。业务端只负责提供内容与表演意图，不读取中间 PNG、模型类别编号和缓存目录。

角色配置至少包括说话/待机素材、声音、允许的表演意图和渲染配置。时间轴使用秒或明确的有理数时间基准；帧索引只能由帧率推导，不能用固定的 120 帧代替时长。

## 当前脚本距离复用的具体差距

- `settle_speech_tail.py` 写死三个名字、120 帧、30 FPS 和 v3 输入路径；缺少可变时长、全静音、无尾部空间、较短素材的策略。
- `prepare_complete.py` 固定 4 秒附近的音频长度；需区分「语音原时长」「素材不足」「允许变速」等策略，不能默认截掉尾音。
- 对超过素材长度的语音，可重新选取/拼接可衔接素材，或生成更长动作；应明确失败，而不是重复不匹配的帧。
- 服务器通过固定版本文件名猜最新合集，片段元数据靠独立写入；应改为经过验证后原子更新的发布清单，使单片、待机、合集和报告属于同一版本。
- `result.json` 的 `seconds` 等字段存在沿用前阶段数据的问题；应分别记录 `media_duration_s`、`stage_timings_s`、`total_render_s`，每项都带本次任务版本，避免旧指标混入新结果。
- 生成脚本和校验脚本重复读取视频、编码与裁剪逻辑；可提取公共媒体工具，但回归检查应尽量从外部结果验证，避免测试与实现共享同一错误假设。
- 缓存键应由输入音频/素材哈希、模型版本和配置组成。新台词必须使音频特征缓存失效；不能因目录中已有输出就跳过处理。
- 角色资产与机器路径分离，模型依赖记录版本和哈希，密钥继续只放在服务端。

## 如何证明已能复用

先固定一组覆盖正常短句、长句、句中停顿、轻声尾音、笑声、全静音、快速打断、触脸遮挡和不同帧率/时长的样例。模型或参数更新必须回放同一组输入。

检查分为三层：

1. 文件与时间：音频完整、媒体可解码、时长/帧率/采样率正确、无多轮时间漂移。
2. 行为与合成：口腔类别覆盖正确、背景/身体不受误改、没有过早截断尾音、静音不残留生成嘴型、状态切换姿态连续。
3. 人工观感：发音是否匹配、牙齿是否重影、嘴角是否变形、身份是否稳定、动作是否符合意图。像素残差不能替代这一层。

最小复用验收不是「原来三个场景还能播放」，而是新角色配置、新台词和不同时长可以经同一入口生成完整媒体包，不修改脚本常量，并留下准确的版本与报告。

## 实施顺序

第一步：保留当前可回滚输出和三次修复的回归样例，整理角色资源包与时间轴；抽出离线渲染入口，去掉名字、时长和帧率常量。先交付可复用的离线能力。

第二步：独立播放器与状态控制器，覆盖待机、开口、收尾、暂停、打断及多轮切换；优先改善动作素材和衔接质量。

第三步：在前两步验证后接入业务对话。预生成常用回应可以先落地；自由对话需要再解决语音流、视频缓冲、生成延迟和取消。现有几秒视频的离线生成耗时不能等同于实时对话延迟。

优先级最高的沉淀目标是「稳定的角色表演与播放流程」，随后再扩大情绪和动作覆盖。
