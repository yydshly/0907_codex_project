## 同输入对照与采用的优化

### 1. 保持像素一致的局部混合

原实现对整张 512×768 图像进行浮点乘加与取整；改为仅对人脸变换覆盖的矩形计算混合，其他像素直接保留。

仿射采样仍在完整画布上执行。尝试过把仿射原点也平移到小矩形，速度更快，但会改变 OpenCV 的取整，出现极少数像素 1–2 色阶差异，因此没有采用该变体。

安慰、轻微不满两组共 200 帧的混合对照：约 1.69→0.63 秒、1.64→0.55 秒，200 帧像素完全相同。这里测量的是混合步骤，不是整条视频的三倍提速。

### 2. 重叠执行下一句 GPU 推理与上一句 CPU 合成

旧调度：第一句推理 → 第一句合成 → 发布 → 第二句推理 → 第二句合成。

新调度：第二句音频准备好后提前入队；第一句 GPU 推理结束后交给单独的 CPU 合成线程，GPU 随即处理第二句。最多保留两个未完成的合成任务，CPU 合成仍为单线程队列，GPU 推理仍串行执行，避免无界并发。

使用上一版完全相同的两段 WAV 和相同动作偏移重新生成：

- 新任务：`2885ff5a1de9435b9452f7a06559b83d`、`b67b40f5d2f74b1b86323e37f7bc0715`。
- 两段共 157 帧，最终 MP4 解码画面与旧视频逐像素一致，MSE=0。
- 观察到上一句 CPU 合成与下一句 GPU 推理重叠 1.188 秒。
- 按片段就绪时间估算的句间欠载为 1.763 秒。这个值不是浏览器实际播放测量，也不包含 MiniMax 对话和 TTS 耗时。
- 第一段自身生成耗时 7.172 秒，与旧样例 7.281 秒接近。线程重叠主要让下一句提前就绪；CPU 资源竞争会抵消部分首句合成收益。

对照证据：[混合微基准](avatar-composite-benchmark.json)、[同音频视频对照](avatar-overlap-benchmark.json)。

### 3. 没有采用的推理设置

同一批 32 帧比较批量 4/8/16、普通内存布局与 channels-last。旧配置约 1.77–1.83 秒，候选约 1.66–1.72 秒，提升有限且存在细小数值差异，因此保留旧配置。

分项显示图像解码约 1.27 秒、嘴型 UNet 约 0.48 秒。后续模型吞吐优化应重点测量解码器，不能只增加 UNet 批量。记录：[推理微基准](avatar-inference-benchmark.json)。

## 稳定性与取消

真实页面首次试验触发 Windows 的瞬时文件句柄争用：读进程暂时占用任务 JSON 时，原子替换返回 `PermissionError`。已在公共写入协议中增加最多 12 次有界重试，始终保留完整的旧 JSON，并清理临时文件。永久失败仍抛出错误，不吞掉错误，也不改成非原子覆盖写入。

同时修复前端切换新会话期间仍可提交的竞争：初始化和新会话加载完成之前禁用提交，防止请求写入旧会话。

真实取消验收：

- MiniMax 对话阶段取消后，0.375 秒释放本地资源，新请求随后成功完成。
- 在上一句后处理、下一句推理重叠的窗口取消，0.344 秒释放资源；父任务取消，并清除子任务请求文件。
- 远程 HTTP 请求的取消语义仍是本地停止等待和丢弃旧结果，不能撤销供应商已经发生的远程计算或计费。

记录：[真实请求与重叠阶段取消](dialogue-overlap-live.json)。

最终检查通过：18 项 Python 测试、浏览器播放器状态测试，以及六类模板和 27 条真实视频的音轨同步、静音闭口帧与缓存一致性检查。测试过程中发现的问题已修复后复测；这些检查仍不能替代人物自然度的主观评价。

## 复用与验证

协议继续兼容 `/api/dialogue/turn` 的 `mode: "segmented"`，客户端仍按 `segments` 逐项播放，无需知道 CPU/GPU 调度细节。

关键实现：

- `scripts/performance_postprocess.py`：完整仿射采样 + 局部混合。
- `scripts/performance_worker.py`：有界后处理队列；指标记录 GPU 与后处理起止时间。
- `scripts/dialogue_segments.py`：第二段提前入队；偏移使用实际 PCM 帧数，保持动作时间线接续。
- `scripts/performance_jobs.py`：Windows 原子替换重试。
- `demo/dialogue-segmented.js`：会话切换期间的提交保护。

```powershell
& ./.cache/sadtalker-venv/Scripts/python.exe -m unittest discover -s scripts -p 'test_*.py'
node scripts/test_segmented_player.cjs
& ./.cache/sadtalker-venv/Scripts/python.exe scripts/verify_performance.py
# 在服务空闲时运行；下一条会消耗真实 MiniMax 额度：
& D:/software/python310/python.exe scripts/verify_segmented_live.py --report dialogue-overlap-live.json --overlap-cancel
```

前版关键代码保存于 `.cache/releases/dialogue-segmented-v2/`，附 SHA-256 清单。需要回退时，空闲状态下恢复清单中的文件并重启 server 与 worker。已有旧版视频和更早基线继续保留。

## 尚未达到的目标

目前仍未达到自然实时对话：首句需要完整 MiniMax 回复、首段完整 TTS、首段画面生成后才开播。下一阶段应分别降低 MiniMax 的首段语音就绪时间和图像解码耗时；如果采用更快的解码模型，必须重新验证嘴部、牙齿与说话结束后的稳定性。延后开播增加缓冲可以减少句间停顿，但会增加首句等待，不能计作模型提速。
